# Подбор бижутерии на 1688 под WB

Механизм, которым собирались заказы бижутерии в октябре 2026 года:
- 23.10 — 100 позиций;
- 24.10 — 200 позиций;
- 26–27.10 — 1000 позиций по 100 шт и добор комплектов.

История решений и списки отобранных офферов — `history/HISTORY.md` и `history/orders/*.csv`. Кроме них здесь только код и задания для моделей. Данные остаются на диске: выдача 1688, `details.json`, фото, черновики и заказы xlsx.

## Правила отбора

- **Профиль:** бижутерия и комплекты. Основа — колье, чокеры и наборы с колье. Серьги и броши — второй приоритет. Браслеты и наборы без колье не берём: зимой они не продаются.
- **Вкус:** оценка «3 из 5» допускается, если позиция прошла проверку фото человеком.
- **ROI:**
  - формула: `ROI = (0,0343·P − 6,30) / ((22 + 0,285·вес_г)/12,72 + ¥) − 1`;
  - P — цена продажи, не выше 1 600 ₽; для комплектов берём 1 330 ₽;
  - порог — ROI ≥ 100 % при P = 1 330 ₽;
  - ¥ — цена самого дорогого варианта в карточке.
- **Цена закупки:** не дешевле ¥5.
- **Повторы:**
  - позиции из прошлых заказов не повторяем (`PREV_ORDER`);
  - дубли одной модели у разных продавцов убираем (`dedup_models.py`).

## Конвейер

1. **Поиск — `search/`.**
   - Запросы «стиль × тип изделия» к выдаче kq: `s.1688.com/kq/-<GBK hex>.html?beginPage=N`.
   - Выдача читается в фоновой вкладке Chrome через AppleScript (`tools/chrome_bg.sh`), без курсора и без переключения окон.
   - Скрипты: `kq_wide.py` — широкий поиск, `kq_sets3.py` — только комплекты. Их цепочки `chain_*.sh` при капче делают паузу на час.
   - Капчу и слайдер не обходим.
2. **Кандидаты — `pipeline/wide_prep.py`.**
   - Фильтры: стоп-слова, серебро, ¥5–30, не меньше 30 продаж, без браслетов и колец.
   - Кандидаты нарезаются порциями для Codex, фото скачиваются.
   - `SETS_ONLY=1` оставляет только наборы с колье, `CHUNK` задаёт размер порции.
3. **Оценка вкуса — Codex.**
   - Задание `prompts/TASK_codex_taste6.md` → `codex_taste_wN.json`.
   - Порции крутит `wide_runner.sh` (или `sets_runner.sh` для комплектов).
4. **Проверка фото человеком — `pipeline/wide_review.py`.**
   - `montage` — листы по 48 фото.
   - `verdict` — коды с/о/у/н записываются в `photo_review.json`.
5. **Карточки — `fetch_details.py` и `fetch_loop.sh`.**
   - Собирают цену вариантов и вес из карточки 1688 в `details.json`. Запись атомарная.
   - `sets_queue.py` ставит новые одобренные позиции в начало очереди.
6. **Черновик — `build_order.py`.**
   - Вкус × цена × вес → ROI и вердикт: «брать», «брать при 1 330 ₽», «условно» или «нет».
7. **Заказ.**
   - Одиночные позиции — `build_100.py N OUT.xlsx`. Env: `QTY`, `SKIP_SEG`, `ONLY_SEG`, `SEG_CAP`, `PREV_ORDER` (через `|`), `EXCL_IDS`, `DUMP`.
   - Комплекты — `build_sets.py N OUT.xlsx`, режим `NECK_ONLY=1`:
     - готовые наборы одной фабрики;
     - сборные пары «колье + серьги» разных фабрик. Пары предлагает Codex по заданию `prompts/TASK_codex_sets7.md`, затем `pair_montage.py` и `set_verdicts.py`.
8. **Дубли моделей — `dedup_models.py`.**
   - Похожесть фото: CLIP + phash.
   - Листы пар проверяются глазами, в каждой группе остаётся одна позиция.

Старый путь, через витрины фабрик: `match.py`, `prep_kimi.py`, `merge_scores.py`, `pipeline.sh`, `after_scan.sh`, `tools/scan_factories.py`. Сейчас витрины упираются в слайдер, поэтому основной источник — выдача kq.

## Запуск

- Пути к данным прописаны абсолютными (`/Volumes/ADATA SD810/WB/Подбор/...`). Это снимок рабочих скриптов, а не библиотека.
- Долгие процессы запускаются отвязанными от сессии и с запретом сна:
  `perl -MPOSIX -e 'POSIX::setsid(); exec @ARGV' nohup caffeinate -i ./script.sh`.
- Если закрыть крышку, Mac всё равно уснёт, и вкладка Chrome начнёт отдавать `chrome-error`. `kq_sets3.py` в этом случае повторяет страницу, а если не помогло — останавливается.
- `fetch_details.py` нельзя прерывать посреди записи. 27.10.2026 оборванная запись `details.json` стёрла 1073 карточки, поэтому теперь файл пишется атомарно.
